# Boilerplate CMS V2.5.0 — Final Integration & Security QA

**Release:** V2.5.0-QA1 — final integration and security QA candidate (not Stable, not approved production)

**Baseline:** User-approved V2.5.0-RC5b Development Candidate. Product version metadata stays `2.5.0`.

**Boundary:** Static source/behavior probes on an isolated copy of the release files. The normal QA commands in this release never access the owner's active database, `.env` or uploads. The optional `verify-fixture` is explicitly destructive to an **isolated synthetic fixture** (migration DDL + media index rebuild), and must never be used with a real site database. No active-DB import, migration, restore, mail delivery or deployment is performed during this QA release.

## Security scope and observations

- **Auth:** `password_verify()`, session renewal, server-side user revalidation, remember-token verification and logout revocation found in Core. Full multi-device session invalidation/2FA is a future design option, not implemented here.
- **Admin authorization:** Core and routed module handlers check authentication, mandatory password change, declared capabilities and POST CSRF. AJAX dashboard saves the current account only, through allowlisted metrics; negative tests reject spoofed arrays, invalid keys, duplicate selections and unauthorized role/capabilities.
- **Output injection:** AdminEscaper and AdminRequest negative tests cover dangerous schemes, header/control injection, attribute/HTML output and typed input. These are representative controls, not exhaustive taint analysis of every dynamic template.
- **Public rendering:** Legacy URL validator, Gallery Lightbox and frontend authenticated toolbar guards checked. Real shared proxy behavior (including `Vary: Cookie`, auth `no-store`, subdomain/HTTPS/canonical redirects) requires staging.
- **Uploads:** Apache denies executable upload extensions and internal includes; real MIME parsing, image bombs, Nginx/PHP-FPM configuration, file permissions and CDN handling require staging.
- **Migrations:** Core migration checksums retained byte-identically. Actual RC4b/RC5 DB migration and rollback can only be certified by a separate disposable database.
- **Production policies:** CSP/HSTS headers are not asserted as present in all deployments; evaluate only after HTTPS/proxy/browser testing, preferably CSP Report-Only first. No automatic plugin updates or 2FA introduced in this release.

## QA commands and side effects

| Command | Effect |
| --- | --- |
| `sh tests/integration/run.sh verify-code` | Reads versioned source, performs PHP unit/contract regressions; no live DB or HTTP. |
| `sh tests/integration/run.sh verify-security` | Static security checks only, no DB/HTTP. |
| `sh tests/integration/run.sh verify-install` | Static installation/update preflight, no DB/HTTP. |
| `sh tests/integration/run.sh verify-backup` | Static backup/rollback preflight, no actual restore. |
| `sh tests/integration/run.sh verify-production` | Static source gate only; **not go-live approval**. |
| `sh tests/integration/run.sh verify-site` | Reads existing DB metadata (no fixture writes) and performs **admin-only** HTTP GET smoke by default. May open an anonymous PHP session; does not call public scheduler by default. |
| `CMS_TEST_PUBLIC_GET=ISOLATED_SITE_SCHEDULER_WRITES_OK sh tests/integration/run.sh verify-site` | **Opt-in for isolated staging only:** frontend GET may run due scheduled publishes/unpublishes. Do not use on the active site's DB. |
| `sh tests/integration/run.sh verify-fixture` | **Writes** DDL/index state to a specifically guarded disposable synthetic MySQL DB, and runs rolled-back cross-module transactions. Never run against active site DB. |

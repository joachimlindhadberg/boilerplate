# Boilerplate CMS V2.5.0 — Release readiness / GO-LIVE gate

**Decision: NO-GO for public Stable release.** Packaging and documentation can be prepared without authorizing public deployment.

**Last locally owner-approved cumulative development base:** QA1 **4A.6.9i3 – Gallery UI & Core Icons** (25 October 2026). **Software version:** `2.5.0`. This candidate includes the keyless installer, one active uploads directory, responsive image variants, Page Builder Gallery display settings and Core icon alignment. Previous RC5b and older QA1 notes remain historical evidence, not the current release baseline.

## Verified to date

- The owner locally tested fresh installation, login, uploads, responsive images and Gallery/Page Builder presentation, and explicitly approved 4A.6.9i3.
- Earlier isolated backup/restore/rollback tests passed with documented limits; they are **not** a full restore/rollback of a public production installation.
- Source-level code, security, integration and package checks have been exercised; results are environment- and test-scope-specific.
- A very early CMS version previously ran on a Simply.com account, but that **does not verify 2.5.0** and the active website must remain untouched.

- Read-only Update Compatibility Preflight and **non-installing production ZIP review** services are retained internally; the administrator-facing screen is the simple **Updates** view, and online lookup is not yet connected. They do not establish a supported update path, authenticate a release, or satisfy the backup/rollback gate.

## Remaining pre-public-release decisions/gates

| Priority | Gate | Pass criterion |
|---|---|---|
| BLOCKER | Independent hosting/runtime proof | 2.5.0 installed on an isolated **real supported** Apache/HTTPS webhost (not the active website); log actual PHP/MySQL versions and DB privileges, cookies, private webroot and upload security |
| BLOCKER | Keyless first-run ownership safety | New deployment is protected against first-visitor takeover until an administrator is established, using documented host access restriction or separately approved equivalent |
| BLOCKER | Database/host support statement | Declare only verified database/PHP/Apache combinations; do not claim MariaDB, MySQL 8.4 or PHP 8.3 runtime PASS without evidence |
| BLOCKER | Open-source licensing | Select an explicit distribution license, publish its terms in the release, and review bundled third-party licensing; currently no LICENSE/COPYING file is shipped |
| BLOCKER | Safe existing-site update policy | Decide and verify supported update path for affected existing installs, or explicitly constrain first release scope; never suggest overwriting live sites without backups/migration controls |
| BLOCKER | Backup/restore and rollback | Demonstrate on isolated target hosting profile with independent test data, and validate fallback after a failed update |
| REQUIRED | Packaging integrity | Distribution ZIP source-matched, permissions safe, **one uploads root**, no uploads/credentials/tests/historical developer release notes; archive checksums recorded |
| REQUIRED | Installation documentation | Current keyless installer flow, hosting/layout constraints, failure handling and customer-facing limitations documented |
| REQUIRED | Owner approval | Owner explicitly authorizes Stable/public release only after gates have passed |

## Safe offline package check (development archive only)

```sh
sh tests/integration/run.sh verify-production
python3 tests/release/production_zip.py build '/safe/output/Boilerplate-CMS-V2.5.0-PRODUCTION-RELEASE-CANDIDATE.zip'
python3 tests/release/production_zip.py verify '/safe/output/Boilerplate-CMS-V2.5.0-PRODUCTION-RELEASE-CANDIDATE.zip'
```

The source-only checks do not connect to MySQL, load a webpage, exercise host-specific `.htaccess` enforcement, or authorize production deployment. Never run `verify-fixture` against the active CMS database. **No external webhotel has been tested with this 2.5.0 candidate as part of this packaging task.**

# 4A.6.8a – Device-scoped sessions, password revocation (QA candidate)

**Not a public production release.** Based on the locally approved 4A.6.7a candidate.

- Keeps PHP sessions; adds private `auth_sessions` registry, 256-bit random login and remember secrets, SHA-256 hashes only at rest.
- Every device has its own login/remember record. Logout removes only the current record. Remember-cookie use rotates both secrets atomically.
- Role/status/admin password reset invalidates all sessions. Self-service password change revokes other sessions, rotates current secret and clears its remember-cookie. Ordinary password hash rehashes do not revoke sessions.
- Active session check must find a matching registry record; revoked and pre-migration PHP sessions fail closed.
- No new admin UI, cookies/analytics/tracking, API endpoints, or frontend CSS in this step. `SessionManager::listForUser()` exists for future Active Sessions UI; display must account for stale PHP sessions.

## Schema and deployment order

1. Only use an isolated, backed-up QA DB; ensure `auth_sessions` is absent.
2. Import `database/migrations/20261023_auth_sessions_v2_5_0_qa1.sql` **once using phpMyAdmin**, before updating PHP code. Do NOT import `database/install/empty-schema.sql` over an existing installation.
3. Install the cumulative QA candidate onto a separate code folder; preserve that site's own `.env`, `uploads/` and database.
4. Refresh/login: existing active sessions and existing Remember Me cookies must log in again. This is intentional. Check admin login, Remember Me, logout, password change, role/status change, CSRF and editor permissions on a disposable account.
5. Rollback: restore previous 4A.6.7a PHP code AND the pre-migration DB backup if you need exact pre-upgrade login state. Simply dropping a new table is not a complete rollback; coordinate with user.

## QA scope/limits

- Syntax and source regression checks run without a live database; actual multi-browser MySQL behavior is **not** yet verified.
- Do not deploy to production. Verify phpMyAdmin migration, fresh installer, request-level cookie/header behavior, and local rollback separately before approval.
- Legacy single `users.remember_token` is preserved for backward compatibility in this candidate but is no longer used by the updated Auth code.
- Database registry rows can remain for expired PHP sessions; a later lifecycle/retention audit may introduce cleanup and a fully designed UI.

# Boilerplate CMS v2.5.1-beta.3 – Minimal Updates picker (QA)

## Scope
- Remove the permanent Stable/Beta update channel UI and persistence action.
- After **Check for updates**, display latest eligible Stable and newest Beta/RC when it is newer than latest Stable.
- Filter out versions not newer than the installed version and all draft/invalid releases.
- Select a single release via radio input; default to Stable when both are available.
- Install only the chosen publisher-pinned GitHub asset after rechecking the live catalog, CSRF, full release identity, checksum, ZIP review, backup and maintenance gate.
- Dashboard update notice also uses the available-release discovery instead of a saved channel.
- Reuse the existing updater; no user-supplied URL/ZIP, no new tables/migrations, no module changes.
- Keep database migration releases blocked pending verified production SQL restoration.
- Keep all UI styling in Core admin.scss and compiled admin.css; translations supplied in en/da/de/sv/nb.

## QA boundaries
- PHP syntactic, Core Code Audit, component tests, synthetic release picker tests, and production ZIP build can be checked offline.
- This QA candidate must be deployed and browser-tested locally before creating a GitHub prerelease for beta.3.
- Live release discovery/installation, recovery, and production web-host compatibility are **not** validated by fixture tests.

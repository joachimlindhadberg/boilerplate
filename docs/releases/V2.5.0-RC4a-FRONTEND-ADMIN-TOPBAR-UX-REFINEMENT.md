# Boilerplate CMS V2.5.0-RC4a – Frontend Admin Topbar UX Refinement

**Status:** Development/Production Candidate; awaiting local user approval. **Base:** RC4; RC3 remains last user-approved stable development base. No other feature phase is included.

## Small UI change

- **CMS** is the **only** dashboard link. The redundant standalone **Dashboard** shortcut and duplicate Dashboard link inside **Min konto** are removed.
- **Rediger side** and **Ny side** remain available only under the existing `content.manage` authorization. A role with no such permission no longer gets an empty shortcuts `<nav>`.
- **Min konto** shows the escaped account name when available and the unchanged POST + CSRF-protected **Log ud** action. No invented profile-management route is introduced.
- The toolbar is **fixed** at the viewport top (`40px` height). The frontend theme reserves `40px` of page space *only when the bar is rendered*, moves the sticky site header to `top:40px`, and positions the mobile navigation below both bars (`104px`), and offsets in-page anchors below the two bars. No extra HTML layout wrappers, JavaScript, or inline styles.
- Only the frontend-theme SCSS partial and its compiled stylesheet change; they are synchronized. Core continues to generate semantic accessible markup, and auth/caching policy is unchanged.

## Verification and local test

```sh
sh tests/integration/run.sh verify-code
php tests/frontend-admin-topbar-rc4a.php
```

On an existing local site, check a logged-in admin/editor at 320px, 390px, 768px and desktop sizes while scrolling: toolbar stays fixed, site header and mobile menu are not covered, dropdown opens and Log ud works; on a logged-out/private window there is no bar or extra 40px offset. The public account menu must no longer contain Dashboard; CMS is the only Dashboard shortcut. Test role without `content.manage` if available. Browser rendering and any shared proxy/CDN cache still need separate manual checks before production. Never run `verify-fixture` on the active database.

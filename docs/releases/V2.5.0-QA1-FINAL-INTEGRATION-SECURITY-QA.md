# V2.5.0-QA1 — Final Integration & Security QA

Candidate built on the latest approved RC5b; runtime product remains `2.5.0`.

This release corrects outdated migration fixture expectations (5 → 7), extends the optional rollback-only synthetic integration workflow to Gallery Lightbox and per-account Dashboard Cards, and prevents standard admin HTTP smoke tests from unintentionally invoking the public traffic scheduler. The explicit `CMS_TEST_PUBLIC_GET=ISOLATED_SITE_SCHEDULER_WRITES_OK` opt-in enables the old public GET checks only when schedule side effects are acceptable on an isolated staging site.

Adds `tests/final-integration-security-qa-v2_5_0.php`, a DB/HTTP-free suite of negative security input, role, routing and integration invariant checks, plus the audit report at `docs/audits/V2.5.0-FINAL-INTEGRATION-SECURITY-QA.md`.

**Changed runtime:** none. **Changed historic migrations:** none. **New migrations:** none. **Changed frontend/CSS:** none. **User data:** never touched. Production candidate remains a candidate: full staging, HTTP browser flows, actual MySQL fixtures, mail/cron, restore and rollback are not certified by source checks.

Recommended commands after local installation (code-only):

```sh
sh tests/integration/run.sh verify-code
sh tests/integration/run.sh verify-security
sh tests/integration/run.sh verify-install
sh tests/integration/run.sh verify-backup
sh tests/integration/run.sh verify-production
```

The `verify-fixture` branch runs only when you expressly set up the disposable guarded MySQL database with its dedicated account and marker. Never run it on a live or ordinary developer site database.

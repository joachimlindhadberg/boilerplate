# V2.5.0 QA1 — 4A.6.9f1 Quiet Hosting Preflight UI

**Base:** 4A.6.9f Installer UI/UX test candidate. **Status:** separate local QA candidate, not a public release.

## Change

- The Database step displays **no hosting success status, badge or expandable requirements panel** when all mandatory hosting requirements are met.
- If a mandatory hosting requirement fails, a plain-language warning appears. An optional **Technical details** expander lists only the failing mandatory requirements and corrective guidance.
- When there is a mandatory failure, **Test connection** remains disabled. The private server-side preflight is still enforced before the database connection test and before installation DDL; nothing about its checks, permissions or authorization has changed.
- Modal layout, step indicator, fixed footer, Back behavior, password handling and keyless installation security are unchanged.
- Installer SCSS/CSS stay byte-identical. CSS cache version is 4a6.9f1.

## Testing

- PHP regression suite, installer preflight/source audit, keyless HTTP smoke test, installer UI/session/Chromium tests, and a new isolated dual-state (success/failure) HTTP test.
- No real MySQL installation and no external shared-hosting deployment were tested by this UI-only change.

## Local QA

1. Install into a **separate local test site** with a **fresh empty DB**; do not replace or modify your currently approved site.
2. At the Database step, verify that **no hosting status panel** appears on a compatible host and that **Test connection** works.
3. On a disposable copy only, temporarily create a mandatory preflight failure (e.g. remove a packaged upload `.htaccess`), refresh and check that an explanatory warning appears, the **Technical details** section describes the problem, and **Test connection** is disabled. Restore the fixture file afterward.
4. Verify fixed footer, Back/Next navigation and installation/login as needed. Do not run any destructive database tests against an existing database.

**Security:** As before, an unconfigured public site using the keyless installer requires hosting-side access restriction before first owner setup to avoid first-visitor takeover. No new protection is claimed in this UI-only revision.

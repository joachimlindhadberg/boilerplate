# Boilerplate CMS V2.5.0-RC3 – Frontend Markup Hardening

**Status:** Development/Production **candidate** for local review; no stable or go-live approval.  
**Source base:** User-approved V2.5.0-RC2 – First-Time Installation Wizard.  
**Internal runtime version:** `2.5.0` (unchanged until Stable).  
**Scope:** Phase 3 only: public HTML output and semantics; no admin topbar or dashboard changes.

## Changes, tracked against the RC2 frontend audit

- **FO-01 / FO-06:** All Page Builder CTA/link output paths now call the same public URL validator, including legacy Hero, legacy CTA and shared legacy/V2 grid children. Paths with unsafe schemes, backslashes, control characters or raw whitespace are dropped at render time even if a previous import bypassed the editor. Allowed root-relative paths, fragments and HTTP(S) links remain supported. Image sources are also checked at output: local `/uploads/`, legacy `/assets/uploads/` and HTTP(S) media URLs are supported. No imported data is modified.
- **FO-02:** Repeated instances of one public Forms component receive unique wrapper and field ids (`form-7`, `form-7-2`, etc.) including label, help/error and radio-option associations. The original `form_id`, form token, validation, honeypot and submission endpoint remain unchanged. A small `form_instance` POST field directs existing session flash feedback and post-submit anchors to the correct visual instance, defaulting safely to the first instance if absent/invalid.
- **FO-03:** Invalid or inactive component references and active components that render no output do not produce empty public sections when no editor heading is set. Intentional editor heading-only components and empty grid Rows remain supported; legacy asymmetric and V2 layouts retain their wrappers, data attributes and CSS hooks.
- **FO-04:** Removed the unconditional `/admin` shortcut from the **public footer**. Authentication and the actual admin route are untouched. Phase 4's authenticated topbar is NOT implemented here.
- **FO-05:** Header mobile-navigation toggle is emitted only alongside rendered navigation. Empty assigned menus no longer produce empty navigation markup, and the pre-migration navigation fallback now includes the accessible name `Hovedmenu`.
- **FO-08:** When an existing media-library record includes positive, reasonable image dimensions, Page Builder uses HTML `width`/`height` attributes to reserve space; invalid/absent metadata is omitted. No inline styles or CSS ownership changes.
- **FO-09:** Forms omits inert `placeholder=""` attributes. Necessary form rows, columns, hidden fields, tokens, and feedback are retained.
- **FO-07, other low-priority audit notes:** No class renaming or speculative removal of theme styling hooks, stylesheets or JS. The public HTML contract and external themes take priority over cosmetic shortening.

## Isolated test coverage

`php tests/frontend-markup-hardening-rc3.php` exercises the real Page Builder and Forms rendering methods without CMS bootstrap/DB. It checks dangerous/allowed URL schemes, legacy unequal grids, V2 1–6 grid columns, multiple public forms, unique ids/ARIA, flash routing, module no-output cases, and code-level nav/footer safeguards. `sh tests/integration/run.sh verify-code` runs the existing source and PHP regression tests plus this new file; it is read-only.

Other read-only source checks:

```sh
sh tests/integration/run.sh verify-security
sh tests/integration/run.sh verify-install
sh tests/integration/run.sh verify-backup
sh tests/integration/run.sh verify-production
```

**Limitations:** The checks do not prove live server rendering, actual MySQL requests, CSS layout, keyboard/screen-reader behaviour, form delivery, or staging/production readiness. This environment lacks `mysqli`/`mbstring` and a connected MySQL test instance. The installed site and active DB were not accessed. No `verify-fixture` or migration/restore operation was run.

## Safe local verification before approval

1. Back up the existing RC2 installation and DB. Update only the release code, retaining the original `.env`, DB and uploads. Prefer a separate cloned local site and never overwrite an active database with any ZIP.
2. Check public pages with legacy unequal-width grids, V2 grid layouts (1–6), Hero, text, images, CTA and Gallery. Ensure intended empty Rows still display as designed and no builder styling is lost.
3. Check a page with the same form inserted twice: distinct labels/id targets, required fields, errors, success message, spam honeypot and redirect anchor for both instances. Verify that the first form's historical `#form-ID` anchor still works.
4. Check empty and populated navigation, mobile toggle, keyboard Escape, menu sublevels, and the absence of the public CMS footer link. `/admin` remains accessible by direct URL.
5. Verify the existing RC2 install wizard remains functional on a **separate empty test database** if desired; RC3 does not modify its runtime code. Do not run fixture tests against a real installation.
6. Final production release requires independent staging and production go-live checks per `docs/deployment/V2.5.0-GO-LIVE-GATE.md`.

RC2 remains the most recently approved rollback point until explicit user sign-off on RC3.

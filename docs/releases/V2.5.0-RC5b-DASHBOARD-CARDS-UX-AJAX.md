# V2.5.0-RC5b – Dashboard Cards UX & AJAX Refinement

**Status:** Development + Production Candidate; local user acceptance required. Latest expressly approved rollback base remains RC4b. This RC5b is based on RC5a, incorporating the fixed direct PHP POST route. CMS runtime version remains `2.5.0`.

## Scope and UX

- The Dashboard retains four per-user metric cards and their existing metric definitions, defaults, color order, and destinations.
- Removes the prominent **Tilpas kort** button and large interactive customization form.
- Each card instead has a discreet Core SVG `···` control in the upper-right corner with a keyboard-accessible dropdown. Selecting an available metric autosaves the complete selection via AJAX, refreshing all four cards' localized labels, counts, destinations and original Core SVG icons **without a page reload**.
- Selecting a metric already on another card swaps the two positions rather than creating a duplicate; all four selections remain unique and server-validated.
- The **Vis velkomst** action is **unchanged in the dashboard titlebar**, and the welcome panel behavior is unchanged.
- Menus close on outside click or Escape, returning focus as appropriate. Busy state blocks double submissions. A failure leaves old data visible, announces failure, and displays the Core notice so the user can retry.
- The original CSRF-protected POST editor remains available **only inside `<noscript>`** for JavaScript-disabled browsers; the browser-visible large panel is removed.

## Security and data

- The distinct `POST /admin/index.php?mode=dashboard-cards-ajax` endpoint reuses the existing admin authentication, forced-password-change gate, role/capability checks, CSRF and `DashboardCards::validate()` whitelist. The server uses authenticated `$auth->id()`, ignoring any user-provided account identifiers.
- JSON responses have `Content-Type: application/json`, `X-Content-Type-Options: nosniff`, and `Cache-Control: private, no-store`. Failures return correct HTTP 403/405/422/503 codes; no redirect with successful AJAX.
- The server returns only Core allowlisted destinations and localized labels; the client writes JSON text with `textContent` and uses pre-rendered Core icon `<template>` elements; no direct HTML injection.
- Existing `user_dashboard_cards` table, migration `core:20261019_200_dashboard_cards`, historical migrations, module versions and frontend/theme code are unchanged. **No new database migration** for RC5b. If RC5 migration is `applied`, do not rerun it.
- Both admin CSS and SCSS are edited in sync. No new libraries, dependencies, CDN, or external service.

## Local acceptance checklist

1. Install RC5b **on a separate test installation** using the Development Candidate, preserving `.env`, uploads and live data. Restart local PHP if stale OPcache is suspected; no migrations if RC5 already applied.
2. Log in and verify **Vis velkomst** has not moved or changed. No global **Tilpas kort** button or big form should be visible.
3. Use `···` on card 1 to choose a previously unused metric. Confirm that the label, count, link and icon change immediately without navigation or refreshing the page.
4. On card 2, choose the statistic already displayed on card 1: confirm that the two cards swap and all four remain unique.
5. Reload the page; selection remains. Log in as a different user; their selection remains independent.
6. Test role/module constraints (no unauthorized or inactive-module choices), mobile dropdown layout at ~320px, Escape/outside-click, keyboard focus, disabled buttons while saving, and network failure (previous content remains, actionable error appears).
7. Check DevTools Network: exact `POST /admin/index.php?mode=dashboard-cards-ajax` returns HTTP 200 and JSON; session errors return 403/redirect which the client treats as failure.
8. Run read-only checks: `sh tests/integration/run.sh verify-code`, `verify-security`, `verify-install`, `verify-backup`, `verify-production`. Use isolated DB for real MySQL workflow tests; **do not run `verify-fixture` or migrations against an active database**.

## Verification boundary

Source and synthetic-browser tests are not a full live Apache/MySQL test with user sessions, database migration, hosting proxy caching, or production deployment. Staging and full restore testing are still pending; this release is **not V2.5.0 Stable Production**.

### Optional synthetic Chromium regression

On a development machine with Python Playwright and Chromium installed, run:

```sh
python3 tests/browser/dashboard-cards-rc5b.py
```

It executes the **actual Dashboard PHP view** through an isolated fixture with fake user/counts, loads the actual Core admin CSS and JS, and simulates POST responses **without connecting to a database or server**. Browser checks cover 320/390/768/1280px, dropdown open/Escape/focus, success response and swap, failed response, and UI recovery. It is not a substitute for local Apache/MySQL authentication and persistence tests.

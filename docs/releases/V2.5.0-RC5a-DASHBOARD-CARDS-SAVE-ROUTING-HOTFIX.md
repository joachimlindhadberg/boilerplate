# Boilerplate CMS V2.5.0-RC5a – Dashboard Cards Save Routing Hotfix

**Status:** Development and production candidate. Awaiting local user acceptance. V2.5.0-RC4b remains the most recent approved rollback reference. RC5a is a narrow fix layered directly on RC5 and includes all RC5 functionality.

## Symptom and analysis

After applying the RC5 dashboard-cards migration, submitting **Gem kort** produced HTTP 405. The RC5 form used `POST /admin?mode=dashboard-cards`, targeting the physical `/admin` directory without a trailing slash. Depending on Apache `DirectorySlash` and rewrite sequencing, a directory canonicalization redirect can change POST into GET on follow-up; the Core action explicitly rejects GET with HTTP 405 (`Allow: POST`). The definitive request/redirect chain still needs confirmation on the user's Apache instance.

## Change (one production PHP file)

In `public_html/admin/views/dashboard.php` the POST action is now `/admin/index.php?mode=dashboard-cards`, matching existing login, logout, language and password POST endpoints and bypassing directory slash canonicalization. The existing `admin/index.php` handler, validation, CSRF token, authenticated account binding, PRG flow, metric providers, Core styles and JS are unchanged.

## Scope and safety

- **No database change or new migration**. The RC5 `core:20261019_200_dashboard_cards` migration is still required exactly once for older installs; if already `applied`, do not run again for RC5a.
- No changes to `.env`, uploads, stored preferences, frontend, module versions, translations or historical migrations.
- Existing GET dashboard address `/admin` stays the same; only the save form POST endpoint changes.
- Regression tests explicitly reject ambiguous `/admin?` POST form actions and confirm the direct `index.php` route.

## Local acceptance test (only on your isolated local/test installation)

1. Back up and overlay RC5a Development Candidate while preserving `.env`, uploads, and your DB.
2. `php core/cli/migrate.php --status` should show `applied core:20261019_200_dashboard_cards`. No migration required if already applied.
3. Log in, open **Tilpas kort**, choose four distinct metric types, click **Gem kort**. It should redirect to Dashboard with success and retain choices across reload.
4. Optionally inspect DevTools > Network > Preserve log: the save request must be `POST /admin/index.php?mode=dashboard-cards` and return a redirect to `/admin?cards=saved`, with no `405`, and the subsequent Dashboard GET succeeds. Note that actual HTTP status/redirect details depend on hosting configuration.
5. Validate that duplicate selections are rejected (client and server) and that other POST actions (login/logout) still work.
6. Run read-only source checks: `sh tests/integration/run.sh verify-code`.

No live Apache/MySQL integration testing has been carried out in the build environment, so local functional approval is still required. This candidate is not a Stable Production release.

# V2.5.0-QA1 – Dashboard Getting Started (test candidate)

**Status:** Isolated test candidate only; no production go-live approval.  
**Baseline:** V2.5.0-QA1 4A.6.3b Core Input Alignment, retaining English Default, 4A.6.2a preflight and 4A.6.3 activation fixes.

## Purpose

Replace the generic recurring “Welcome back” dashboard notice with a concise Getting Started introduction. It appears on the first dashboard visit for a new account/browser and remains hidden after dismissal unless the user selects **Show welcome**. The existing Core welcome-panel visual component is retained.

## Scope

- `public_html/admin/views/dashboard.php`: `GETTING STARTED`, translated introduction, and three relevant shortcuts. **Edit homepage** uses a server-resolved real page ID and falls back to the Pages list if the special homepage is not present. **Site settings** is shown only to users with `settings.manage`; **Edit homepage** requires `content.manage`. **View website** remains available to dashboard users.
- `public_html/admin/index.php`: read-only homepage lookup and capability checks for shortcuts. No new endpoint or database write.
- `public_html/admin/assets/js/admin.js`: account-scoped browser-local v3 dismissal preference; automatically show until closed, never resurface on a 12-hour login timer, preserve older v2 preferences so existing users do not receive unexpected onboarding; retain manual Show welcome and focus handling.
- `core/lang/translations.json`: complete English, Danish, German, Swedish and Norwegian Bokmål translations for the welcome copy and shortcuts.
- No changes to Core CSS/SCSS, frontend rendering, modules, schema, migrations, installation workflow or existing database rows.

## Behavior and limits

- No stored setting is overwritten in the database. The preference is in **browser localStorage**, consistent with the previous implementation. Clearing browser storage or using another browser/device may show the introduction again; true cross-device per-user first-login persistence would require a separately designed server-side preference.
- Older v2 welcome localStorage entries are treated as an indication that the account already had a welcome panel, so the new onboarding is hidden automatically on that same browser after upgrade. Use **Show welcome** to view it on an existing account.
- Installation over an existing test hostname can retain browser-local legacy keys from previously deleted test databases; use a fresh browser profile/Incognito for a fresh-install onboarding check.
- Missing storage access degrades to in-page close/reopen without weakening authorization.
- This is a **source and isolated UI** test candidate; no active databases, servers or CMS installations modified.
